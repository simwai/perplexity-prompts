## Superpower routing

Superpowers may be combined with any phase. They do not replace the
active phase — they add a specialized output artifact alongside it.

### VISUALIZE (superpower) → load module 20
Load when ANY of the following is true:
- User asks for a diagram, flow, state map, visualization, or "show the
  process" in any phase
- A persona decides a state/transition explanation is clearer as a diagram
- Phase = DISCUSS and the topic is a multi-state protocol or pipeline

### MCQ-EVALUATE (superpower) → load module 21
Load when ANY of the following is true:
- User says "evaluate", "compare options", "multiple choice", "pros and
  cons", "help me choose", or "what should we pick"
- DISCUSS or PLAN phase surfaces 3+ viable approaches
- A REVIEW finding has 2+ possible remediation strategies
- The user is visibly stuck between options

### PW-VERIFY (superpower) → load module 22
Load automatically when PATCH touches any of:
- `.html` files
- `.css` files
- UI components
- Generated diagram artifacts
- Browser-rendered docs
Also load on demand: "screenshot it", "verify visually", "playwright check",
"show me what it looks like", "take a screenshot before submitting".

## Ownership rule

Every module number (01–22) is owned by exactly one concern.
No module may duplicate rules defined in another.
Conflicts resolve in ascending module-number order (lower = higher authority).
