# BOOTSTRAP — BabaDev Protocol

This file is the entry point. Read it fully before loading any module.

---

## What this repo is

A set of LLM instruction modules that together implement the BabaDev
collaborative-coding protocol. Modules are plain-text files in `/modules`.
Personas are in `/personas`. This file tells the LLM how to start a session
and which modules to load for each scenario.

---

## Session start — 3 entry points

### A) Single-persona session
1. User names one persona (e.g. "load BabaSensei")
2. Load: 01, 02, 11, 12, 19 (always-on) + persona file
3. Load phase modules from 12-module-routing per the opening phase
4. Write SESSION_STATE.md (see module 19)
5. Emit persona greeting + current phase

### B) Multi-persona session (BabaSensei → BabaTester → GuidedSeniorDev)

Step 1 — BabaSensei
- Load: 01, 02, 03, 10, 11, 12, 14, 15, 16, 17, 18, 19 + BabaSensei persona
- Phase: DISCUSS → DOCS → REVIEW → CONFIRM → PLAN
- Output to save: approved PLAN block + HANDOFF envelope (module 13)

Step 2 — BabaTester
- Load: 01, 02, 04, 05, 07, 10, 11, 12, 13, 19 + BabaTester persona
- Input: HANDOFF envelope from Step 1
- Phase: TEST_STRATEGY
- Output to save: test-strategy block + updated HANDOFF envelope

Step 3 — GuidedSeniorDev
- Load: 01, 02, 06, 07, 11, 12, 13, 14, 16, 19 + GuidedSeniorDev persona
- Input: HANDOFF envelope from Step 2
- Phase: PATCH → (back to REVIEW if needed)
- Output: committed code + SESSION_STATE.md marked DONE

If a step's HANDOFF is incomplete → go BLOCKED (module 09). No guessing.

### C) Discussion-only session
1. No persona named — user wants to explore/discuss
2. Load: 01, 02, 10, 11, 12, 18, 19
3. Phase: DISCUSS only
4. No SESSION_STATE.md required

## Superpowers

Superpowers are opt-in output enhancements. They combine with any phase
and do not replace it. Three superpowers are available:

### VISUALIZE → module 20
Produces an interactive HTML state-diagram artifact.
Auto-load when: "show flow", "diagram", "visualize", "state diagram",
"show the process", or a persona judges a multi-state explanation needs
a visual.

Artifact requirements:
- D3 v7 CDN, single HTML, dark Nexus palette, pan + scroll-zoom
- Node tiers: entry / infra / gate / work / output / terminal
- Animated edge lighting on hover and during playback
- Fixed legend that does NOT overlap diagram content
- Playback panel with ≥2 named scenarios
- Edge labels: monospace bold, paint-order stroke, no overlap
- Parallel/reverse edges use opposite bend offsets

### MCQ-EVALUATE → module 21
Structures a decision as a ranked multiple-choice round.
Auto-load when: "evaluate", "compare options", "multiple choice",
"pros and cons", "help me choose", or 3+ viable approaches surface
in DISCUSS/PLAN, or 2+ fix strategies surface in REVIEW.

Round requirements:
- Recommended option ALWAYS first, marked ★
- Each option: 2–3 concrete pros, 2–3 concrete cons, 1-line verdict
- Options ranked best → worst
- Decision prompt at end: letter to confirm, D to add option,
  X to dismiss, ? to ask clarifying question
- Confirmed choice recorded in SESSION_STATE.md under decisions[]

### PW-VERIFY → module 22
Runs a temporary Playwright screenshot pass before submitting any patch
that touches browser-renderable output.
Auto-load when: PATCH touches `.html`, `.css`, UI components, or
generated diagrams. Also on demand: "screenshot it", "verify visually",
"playwright check", "take a screenshot before submitting".

Verification order:
```
[pw-verify.ts] → manual review → PASS
       ↓
[git add / git commit]
       ↓
[pre-commit hooks: format → lint → tsc → test → secret scan]
```

Script requirements:
- Scoped to touched flows only (not full app)
- Both 1280px and 375px widths per HTML artifact
- Output to `.pw-verify/` (gitignored, never committed)
- Deleted after verification confirmed
- Checklist: no overflow, no clipped text, no label overlap,
  legend visible, dark mode correct, controls visible

## Ownership

Modules 01–22 each own exactly one concern. No duplication.
Lower module number wins on conflict.
Session state lives in SESSION_STATE.md (managed by module 19).
Cross-team requirements live in CHANGES_REQUIRED.md (managed by module 17).
Diagram artifacts live in /docs (managed by module 20).
Decision history lives in SESSION_STATE.md decisions[] (managed by module 21).
Verification screenshots live in .pw-verify/ (ephemeral, managed by module 22).
