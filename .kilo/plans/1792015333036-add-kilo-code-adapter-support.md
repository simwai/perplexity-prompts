# Kilo Code Adapter Support

## Objective

Add Kilo Code as a third first-class platform adapter in the Baba prompt system, mirroring the existing OpenCode and Claude Code adapter patterns. The portable system (`AGENTS.md` + `prompt-system/`) already works with Kilo Code via the shared `AGENTS.md` entry point. This plan adds Kilo-specific agent definitions, command definitions, and config generation.

## Constraint: Kilo Code Uses `.kilo/` (not `.kilocode/` or `.opencode/`)

Kilo Code reads from `.kilo/agent/*.md`, `.kilo/command/*.md`, and `kilo.json` at the repo root.

## Design Decision: OpenCode-Style Adapter

Kilo Code is a Continue.dev fork with an agent/command architecture closest to OpenCode:

- Agent files use full persona system prompt + YAML frontmatter (not Claude's short-reference approach)
- Commands use frontmatter + markdown body (like OpenCode's `.opencode/commands/`)
- Multi-agent `task` spawning works the same way
- Permission model is nearly identical (adds `ask` alongside `allow`/`deny`)

The `adapters/kilo/` structure mirrors `adapters/opencode/`:

- `adapters/kilo/agent/` — persona agent templates
- `adapters/kilo/command/` — command templates

**No `adapters/kilo/kilo.jsonc`** — `kilo.json` is GENERATED from `opencode.jsonc` by `generate-adapters.ps1` (single source of truth).

### 4. Update `generate-adapters.ps1`

Add Kilo Code generation section (after OpenCode section, mirroring `.mcp.json` generation pattern):

1. Add `.kilo\agent` and `.kilo\command` to `$targets` hashtable
2. Generate `.kilo/agent/` from `adapters/kilo/agent/`:
   - Process `.md.tmpl` templates with placeholder substitution
   - Copy plain `.md` files directly
3. Generate `.kilo/command/` from `adapters/kilo/command/`:
   - Process `.md.tmpl` templates with placeholder substitution
   - Copy plain `.md` files directly
4. Generate `kilo.json` at repo root from `opencode.jsonc`:
   - Parse `opencode.jsonc` (strip comments, parse JSON)
   - Extract: `instructions`, `default_agent`, `small_model`, `permission`, `mcp`
   - Drop: `$schema`, `plugins` (OpenCode-specific)
   - Keep MCP block in OpenCode format (`local`/`remote`) — Kilo uses same format
   - Write clean JSON as `kilo.json` (no comments)
5. Add Kilo Code to summary output

## Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Kilo Code config format differs from web research | Medium | Generate `kilo.json` from `opencode.jsonc`; test dry-run |
| Permission keys `skill`/`task` invalid in Kilo | Medium | Drop from templates; use only `edit`, `bash`, `webfetch` |
| Command frontmatter missing required fields | Low | Use minimal: `description`, `agent`, `subtask` |
| Persona colors clash with UI | Low | Use Catppuccin Mocha palette from `05-impl-style.md` |
| Sync robocopy excludes `.kilo` | Low | Add `.kilo` to mirror folders |

## Validation

1. Run `generate-adapters.ps1` — verify `.kilo/agent/`, `.kilo/command/`, `kilo.json` created
2. Verify `.kilo/agent/*.md` have valid YAML frontmatter
3. Verify `.kilo/command/*.md` have `agent` and `subtask` fields
4. Run `.\pre-commit.ps1` — verify no integrity issues
5. Verify `sync.ps1 -DryRun -All` includes Kilo Code files
6. Verify `kilo.json` is valid JSON
